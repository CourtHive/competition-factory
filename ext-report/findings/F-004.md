# F-004 — coverage cannot read a large harvested corpus file

**VERIFIED.** Class T in the corpus harness. This occurs on `7963e36968` with published tests and fixtures.
The output `src-tests-mutations-outcome-owneddirectionwrites-test-ts.jsonl` measured 1,075,571,358 bytes.
`computeCoverage` at `src/tests/testHarness/corpus/coverage.ts:161` tries to read it as one string.
Vitest reports `Cannot create a string longer than 0x1fffffe8 characters`.

```sh
OUTCOME_PIPELINE=v2 pnpm corpus:record
for mode in v1 v2 differential; do
  OUTCOME_PIPELINE=$mode pnpm run corpus:coverage
done
```

The first command exits nonzero for the harvest failures and still writes the JSONL. The coverage command
fails on that generated input. Section 8 and `corpus/README.md` describe JSONL as the scenario format.
The coverage calculation should handle a sequence of valid scenarios regardless of aggregate file length.
**BELIEVED.** A streaming or bounded-buffer reader can preserve existing coverage semantics. The external
replay harness uses a streaming reader for the same input.
