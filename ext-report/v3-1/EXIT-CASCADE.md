# Planning an exit and its downstream placements

**Current baseline.** On the common V2 workload qualified for #6532, 9,127 successful calls still used whole-call recording. Exit was the first uncovered obligation in 3,754 calls and cascade in 2,239. Together they account for 5,993 calls (65.7%). The two largest dispatch groups are winner routes. Each count measures test occurrences. Admission depends on who holds each affected seat and what the call must write there. [Current site census](https://github.com/CourtHive/Mentat/blob/cf8fbf20e7822c12fe6bf339dcffddf553a01862/assessment/2026-11-22-exit-repeat-36/native/candidate-sites.jsonl.gz)

## Target architecture for native exit and cascade planning

**Proposed design for review.** Exit establishes or withdraws a claim to a seat. Cascade computes what else that change entitles the draw to place or withdraw. Both planners use the same placement model inside the existing TypeScript outcome pipeline. The ranked rows below are entry points into this model. A row's call count establishes its priority. Its landing preconditions determine which calls a native planner can own.

### A seat, its occupant and the reason it is held

Resolve a seat by draw, owning structure, matchUp and side. Resolve its structure-level position assignment separately. Keep the original side slot, position and link identity when reading the record. Converted records and crossed links can put the actual occupant somewhere other than the nominal destination. A participant ID alone cannot distinguish two appearances in different structures.

| Fact in the read-only planning view | What the planner must distinguish                                                                                                                                                                                                                                                       |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Seat and assignment                 | An occupied seat, a structural BYE, a reservation created by an exit, and an empty seat whose feeder is pending. Auto-calculation requires two occupied seats holding distinct teams. Advancement opposite a BYE has its own cause.                                                     |
| Origin and support                  | Record which feeder matchUp, side and winner/loser link supports each placement, reservation or relayed exit. Keep both origins of a convergence. Track a director-entered or played result on the destination separately from a result produced by propagation.                        |
| Withdrawal                          | Name the old claim and its actual landing. Retract consequences that depended on it, re-evaluate a convergence against its surviving inputs and preserve independently held seats and results. Unknown ownership on an imported record makes the call ineligible for this native route. |
| Output                              | Fold provisional changes through the existing outcome reducer into a call-local view. Keep ordered record operations and notice intents, including their source context and when the payload is read. Material returns use the values committed by the operation.                       |

For example, a main-draw loser can carry an exit into consolation. If the other feeder is pending, retain the claim. When the other feeder arrives, evaluate the award using both origins. If a later correction removes the first exit, withdraw its relay through any intervening BYE, recompute the award, and follow any displaced onward entrant. If the consolation result was entered independently, apply its existing correction and activity rules before replacing either occupant. This same withdrawal is needed by the ranked clear, swap and remove-directed routes. Resolve **both** winner and loser destinations against the projected placements before accepting any of them. ### Settlement schedule

**Target a dependency-driven fixed point for the admitted portion of the draw.** Seed the worklist with changed facts and any existing settlement obligations that the call can observe. Each rule declares its inputs and the facts it can change. For example, withdrawing a consolation reservation invalidates relays past that seat. Producing a convergence can create a BYE, which makes a previously checked carry eligible again. A changed final can owe a cross-structure placement before a decider can be evaluated. The current ordered passes explicitly revisit those cases. These dependencies give the native planners a reason to revisit individual seats and a way to test that none were missed. [Settlement rules and census witnesses](../../src/mutate/matchUps/matchUpStatus/settleAfterWrite.ts) · [First-entry convergence fixture](../../src/tests/mutations/exitPropagation/aCarryPastAConvergencesByeIsCarriedOnTheFirstEntry.test.ts)

The exit planner resolves policy, old and requested results, and both directions, then proposes the origin and claim changes. The cascade planner consumes those changes through the same rules for placement, withdrawal and re-derivation. For the two highest-volume winner routes, the exit route must justify how the loser is treated, and the cascade route must account for what happens beyond the first landing. Neither can commit a partial direction when the other destination is held. A known illegal placement yields the existing ordered refusal. An unresolved destination yields an abstention before effects.

Drain affected rules in deterministic compatibility order using §5.1, the actual sequence of pass invocations and the existing traversal order within each invocation. A forward placement that restores a BYE can trigger a second carry pass before link cleanup. Qualify that conditional revisit by comparing the first refusal or the ordered notices and clock effects of the successful call. Requeue a consumer when its input changes, even if it already visited that matchUp. Retractions can invalidate earlier conclusions. Finish when every affected rule has seen its latest inputs and no further fact changes. Preserve required same-value writes, clock reads and notices in the ordered output even when no placement fact changed. A repeated unsettled state, unaccounted work outside the dependency set or an uncertified ordering sends the whole call through its existing path before commit. Keep the existing whole-draw predicates as the independent coverage check while qualifying each rule.

E1 ran an extra ordered sweep on 63,433 oracle calls with zero record changes or increases in buffered notice count. This supports using the settled draw as a reference. E1 did not run the proposed scheduler, and the counter misses a same-key notice replacement. Compare exact ordered effects on each admitted step before enabling it. Preserve both bounded outcomes in 7.x. Ordinary loop exhaustion returns `SETTLE_BOUND_REACHED`. Forward exhaustion succeeds with `FORWARD_SETTLE_EXHAUSTED`, identifies the outstanding matchUp and leaves work for the next call. Qualify two adjacent forward cases. If the 64th action clears the last obligation, expect success without the warning. With work remaining, name the first outstanding matchUp in reference order, run the later settlement phases and exempt only the forward-work predicate. Replay the next directive to verify it sees the same remainder. Keep bound-reaching calls on the compatibility path until these controls pass. ## One projected draw for both families

**BELIEVED design.** Resolve the call against its input under §3. Read both feeders, current assignments, prior double exits and the decider from the pre-call view. The key for a landing includes structure, matchUp, side, draw position and the source that earned it. For each withdrawal, find where the participant or claim actually stands. A converted record can put it somewhere other than the link's nominal target. Fold a complete candidate into a private working view. Recompute later landings from that view after each release or advance. If ownership is ambiguous or a settle predicate still reports work, hand the whole call to the recorder before applying anything.

1. **Before direction.** Use the existing ordered refusals. Resolve progression and scoring policy at the call, including explicit false values. Row 12 tests first-match loser eligibility using the player's actual prior match history. Preserve row 22 correction-kind and row 14 activity checks in their existing order. Row 31 checks a held winner seat and a held loser seat before the first write, including the first award of an undecided dual after #6487. The §2 table's blanket dual exclusion predates that fix. A replaced winner's own seat and a yielding propagated BYE can become free. An unrelated participant's seat cannot.
2. **Placing an exit.** Use the existing result and provenance ops for the origin (`setMatchUpResult`, `setSideExitProvenance`). Represent a reservation with the existing assignment/BYE ops on the actual structure and matchUp. With carry switched off, direct the eligible loser ordinarily. With carry on, resolve retirement policy before choosing the delivered status. Preserve the source origin through a BYE relay (`mergeSideExitProvenance`); it can outlive the current result. With a missing second feeder keep the landing pending. With both feeders present, derive the convergence from their two origins and apply the resulting advance exactly once.
3. **Withdrawing and re-entering.** Reverse a dependency only when the prior source earned it. Clear its position and reservation, preserve the opposite side's independent origin and walk the displaced award onward. Use the existing `withdrawBye`, `clearPosition`, `setMatchUpDrawPositions` and result ops. Evaluate the second branch after the first has been folded. Preserve a played downstream result wherever the admitted route only relabels. For deep corrections, visit every changed feeder/side state, including crossings into consolation, playoffs and the decider. Revisiting the same matchUp with a different feeder state is meaningful.
4. **Settling and applying.** Use the §5.1 pass order as the compatibility reference for the dependency scheduler on the projected graph, including reservations, stale origins, carries past BYEs, missed and unearned links, deciders and scored times. A depth limit on a new traversal cannot replace the writer's observable warning and partial-settlement semantics. Preserve the recorder for exhausted, random, temporal or unsupported paths. Apply the projected operations to the real draw only after admission, landing and settlement all succeed.
