Formats: what, how and scoring

Three formats describe a competition. Each answers a different question, and each is stored and resolved on its own.

FormatAnswersShape
tieFormatWHAT is playedThe collections of a TEAM matchUp and how their results aggregate to a tie score
matchUpFormatHow a matchUp is scoredA code: sets or timed segments, games, tiebreaks, overtime and deciders
competitionFormatHOW the sport is playedTimers, timeouts, substitutions, penalties, point vocabulary, the server rule and an optional matchUpFormat
  • tieFormat describes the collectionDefinitions of a { matchUpType: TEAM } matchUp (singles, doubles or any custom grouping), how many matchUps each holds, and how value won in each collection adds up to the result of the tie.
  • matchUpFormat is a scoring code such as SET3-S:6/TB7. The grammar covers sets, timed segments, overtime and final-set deciders.
  • competitionFormat covers what the scoring code does not: timerProfile, timeoutRules, substitutionRules, playerRules, penaltyProfile, penaltyBoxProfile, pointProfile, pointMultipliers serverRule (ALTERNATE_GAMES by default, or WINNER_SERVES) and ratingsPolicy (how a dynamic rating moves on its results: see Ratings Policy). It may also name a default matchUpFormat. See @Types/competitionFormat.

How they nest​

Each collectionDefinition in a tieFormat carries its own matchUpFormat, which is the format of every line matchUp in that collection. A competitionFormat does not sit inside either: it is attached beside them, to an event, a drawDefinition or a structure.

The shipped PICKLEBALL_STANDARD competitionFormat fixture (abridged):

{
  "competitionFormatName": "PICKLEBALL_STANDARD",
  "matchUpFormat": "SET3-S:TB11",
  "sport": "PICKLEBALL",
  "serverRule": "WINNER_SERVES",
  "timerProfile": { "changeoverSeconds": 60, "setBreakSeconds": 120 },
  "timeoutRules": { "count": 1, "per": "SET" },
  "substitutionRules": { "allowed": false }
}

Its matchUpFormat, SET3-S:TB11, is the scoring structure: best of three sets, each set a single tiebreak game to 11. Everything else in the fixture (the server rule, a 60-second changeover, a 120-second set break, one timeout per set, no substitutions, plus its penalty and point vocabularies) is how the sport is played, and none of it can be expressed in the code.

Which format owns time​

Time belongs to whichever format answers the question being asked (CA, 2026-11-04):

TimeOwnerExample
The clock of a scored segment: a timed set, half or overtime periodmatchUpFormatS:T45P, O:2X/T15P, -M:T60
A clock on a single action within play: per attempt, shot or changeovercompetitionFormat (timerProfile)seconds allowed for each penalty kick
How long a matchUp is expected to take, including an allowance for partsscheduling policy averageTimes, keyed by the format code10 minutes added for a likely shootout

A decider with no clock in its code, a tiebreak (TB1, TB7) or a shootout (SO5), has no time dimension: a default duration derived from the code adds nothing for it. A limit on each attempt in a shootout is a playing rule, not a length for the shootout, so it is a competitionFormat timer and never a matchUpFormat clock; and an allowance for the time a shootout usually takes is a scheduling decision, made in the policy, not read from the code. See scheduling pipeline. timerProfile has no field for a per-attempt shootout clock yet (shotClockSeconds is the nearest); when one is needed, it is added there.

Where each is stored and resolved​

FormatStored onResolution orderQuery
tieFormatmatchUp, structure, drawDefinition, event (inline tieFormat or a tieFormatId into tieFormats)matchUp → structure → drawDefinition → eventgetTieFormat
matchUpFormatmatchUp, structure, drawDefinition, event; a TEAM line takes its collection's format from the tieFormatmatchUp → structure → drawDefinition → eventgetMatchUpFormat
competitionFormatstructure, drawDefinition, eventstructure → drawDefinition → eventgetCompetitionFormat

The first level that defines a value wins. A matchUp does not carry a competitionFormat: getCompetitionFormat accepts a matchUpId, but only to find the matchUp's structure and drawDefinition. An event-level competitionFormat is set with modifyEvent({ eventUpdates: { competitionFormat } }); pass null to clear it.

For a TEAM line matchUp, hydration and the scoring write path take the format from the line's collectionDefinition before falling back to structure, drawDefinition and event.

Which matchUpFormat applies​

The ScoringEngine prefers an explicit matchUpFormat option, then competitionFormat.matchUpFormat, then its default format.

No tournament query or mutation reads competitionFormat.matchUpFormat: hierarchical resolution, hydration and score validation use only the hierarchical matchUpFormat, and there is no rule for which applies when the two disagree.

Not to be confused with competitionProfile​

A competitionProfile is a versioned attribute of a drawDefinition that describes the draw's competition format, such as the rotating-partner formats Americano and Mexicano. A competitionFormat describes how the sport itself is played.

Planned​

Planned, not shipped

competitionFormat is planned to carry explicit constraints that narrow which matchUpFormats it accepts, for example refusing a tiebreak final-set decider. Constraints will only narrow: they cannot admit a code that the matchUpFormat grammar refuses.
