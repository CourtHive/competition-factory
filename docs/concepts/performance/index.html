Performance Evidence and Measurement

What improved across 7.x​

Factory reduced repeated hydration, parameter copies, graph scans, venue/participant assembly and tally work. These are historical paired measurements, not fresh benchmarks of the current branch. Release membership follows the first 7.x tag containing the change. See the 7.x overview for the short account.

Elimination projection changed after the tally benchmark​

#5525 removed elimination tallying from public projections. Thus #5522's 72 ms public read is historical, not a current-head benchmark. Its standalone tally optimization remains useful, but does not explain a projection that skips tallying. RR refresh also became group-scoped and policy-aware. See the results contract. Do not multiply gains or infer a new time without measuring the final candidate.

Choosing the work a consumer needs​

  • Use a matchUp ID filter for a targeted read; full structural facts still support completion, progression and TEAM-parent context.
  • Use hydrateParticipants: false when entry metadata suffices. Thin output retains scoring/context facts; it is not raw-state access.
  • Omit recovery calculations when unused. contextProfile.exclude redacts final output; it does not promise that all computation associated with the excluded attributes is skipped.
  • Use structuresProfile: 'STUBS' where supported for a smaller response. Structure/group dependencies can still require full computation.
  • Prefer named governor imports over the aggregate governors object. See bundle measurements.

These caches/indexes belong to one invocation/traversal, not a durable cache across mutations. Do not retain them across writes without owning invalidation. Narrow rollback snapshots require a proven mutation footprint and complete restore evidence before optimization.

Reproducing and extending the evidence​

Build with pnpm build. pnpm verify:consumer-bundle checks bare-engine, named-query, aggregate-query and full-engine fixtures using esbuild bundle/minify/tree shaking, ESM output and gzip level 9. scripts/verify/baseline/consumer-bundle.json budgets raw/gzip growth. A budget is not a fresh timing benchmark. Compare releases using identical fixture bodies and imports.

For timing, pin code, Node and dependency revisions; reuse identical fixtures and histories across versions and record their hashes. Warm up, take enough repetitions for median/p95, control competing load and verify result parity. Separate initialization, operation, serialization and consumer render. Record hydrations/parses/traversals, output bytes and allocations with elapsed time. Counts measure work, bytes measure payload and milliseconds measure latency; none substitutes for the others.

A useful panel is 7.0/7.5/7.10/7.15/next candidate over SE32/128/512, FMLC128, COMPASS64, TEAM16, RR64, multi-event and unrelated-participant-heavy fixtures. Include scheduled/unscheduled and one-ID reads, refresh on/off, line outcomes and rollback-enabled queues. Report regressions as well as gains. Historical timings exclude network, storage and browser rendering. Gains overlap and cannot be added or multiplied; no end-to-end speedup for the whole 7.x cycle has been established.
